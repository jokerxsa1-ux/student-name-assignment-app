# 生徒名かんたん割り当て — MVPシステム設計書

## 1. 文書の位置づけ

本書は、教員がブラウザ上で生徒名を「席」「グループ」「順番」へ割り当てる静的WebアプリのMVP設計書である。実装前の基準として使用し、実装中に仕様変更が生じた場合は本書も更新する。

### 1.1 最優先事項

1. 入力した生徒名、条件、結果を外部へ送信しない。
2. 入力データをブラウザへ永続保存しない。
3. URLを開き、名前を貼り付けた直後から使える。
4. 自動割り当て後に手動修正できる。
5. 条件を満たせない場合は、黙って無視せず日本語で説明する。

### 1.2 MVPに含めないもの

- バックエンド、データベース、ログイン、クラウド保存
- 外部API、AI API、アクセス解析、広告
- Googleサービスやスプレッドシートとの連携
- Instagramを含むSNSの表示、リンク、設定項目、誘導
- 生徒名・条件・結果の端末内永続保存
- 複数クラス管理、CSV入出力、PWA

## 2. 確定した設計判断

| 項目 | 判断 |
|---|---|
| アプリ名 | `生徒名かんたん割り当て`。設定ファイル1か所から変更可能 |
| 技術 | Vite、React、TypeScript、CSS Modules、Vitest |
| 状態 | 通常はReactのメモリ内のみ。利用者が明示的に有効化した場合だけ、暗号化した直近2回の席履歴と名簿をIndexedDBへ保存 |
| 名簿 | 3モードで共通。除外状態も共通 |
| 座席初期値 | 前後5行 × 左右6列。教卓は上側 |
| 上限 | 生徒100人、座席10行 × 10列 |
| 条件優先度 | 固定配置は必須。前方指定と「離す」は最善努力 |
| 探索上限 | 1回の実行につき最大5,000試行 |
| 違反スコア | 前方違反1件＝1点、「離す」違反1組＝1点 |
| 手動修正 | 条件違反が生じても許可し、直後に警告を再計算して表示 |
| 固定配置の手動変更 | 確認後に許可し、固定条件違反として表示 |
| Undo/Redo | 最大50操作をメモリ内に保持 |
| 外部アセット | 使用しない。CSS、画像、アイコン等は同梱またはインライン化 |
| 乱数 | Web Crypto APIを使用したFisher–Yatesシャッフル |
| ダミー名簿 | `児童01`〜`児童30`。常に「撮影用・架空データ」と明示 |
| 席履歴 | 直近2回を参照。同一席を2点、隣接席を1点として類似度を下げる |
| 履歴暗号化 | Web Crypto APIのAES-GCM。パスフレーズは保存せず、メモリ内だけに保持 |

## 3. 実装方針

### 3.1 アーキテクチャ

アプリを次の4層に分ける。

1. **Domain**: 生徒、条件、座席、グループ、割り当て結果の型
2. **Application**: 名簿処理、検証、割り当てアルゴリズム、Undo/Redo
3. **UI**: Reactコンポーネント、入力、結果表示、ドラッグ操作
4. **Infrastructure**: Web Crypto、印刷、ページ離脱警告のみ

割り当てロジックはReactから分離した純粋関数にする。乱数源を引数として注入できる設計にし、本番ではWeb Crypto、テストでは決定的な疑似乱数を渡す。

### 3.2 状態管理

外部状態管理ライブラリは使わず、`useReducer`とContextを使用する。アプリ状態と一時的UI状態を分離する。

- 履歴対象: 名簿、除外、条件、座席設定、グループ設定、結果、印刷設定
- 履歴対象外: 開閉中のダイアログ、トースト、フォーカス位置、ドラッグ中状態
- Undo/Redo: 全体スナップショットを最大50件保持
- モード切替: 名簿と除外は保持し、各モードの条件と結果は個別保持
- 再読み込み: 名簿が1人以上存在する場合にブラウザ標準の離脱確認を要求

### 3.3 対応環境

- 最新の主要ブラウザを搭載したPC、Chromebook、タブレット
- スマートフォンは縦1カラムで主要操作が可能
- Web Crypto APIが利用できない環境では割り当てを実行せず、対応ブラウザを案内

## 6. 自動割り当てアルゴリズム

### 6.1 共通乱数

1. `crypto.getRandomValues()`から符号なし整数を取得
2. 剰余偏りを避けるため、対象範囲に収まる値だけを採用するrejection samplingを使用
3. 入力配列をコピーしてFisher–Yatesでシャッフル
4. 元の名簿配列は変更しない

### 6.2 席替え

#### 実行前検証

実行を止める条件:

- 対象生徒が0人
- 対象生徒数が有効席数を超える
- 同じ席へ複数人が固定されている
- 無効席または存在しない席へ固定されている

実行前に警告し、最善努力で続行する条件:

- 固定席が、その生徒の前方条件と矛盾する
- 前方N行以内に必要な人数が、対象となる有効席数を超える
- 分離条件のある生徒が除外中で、その条件が一時的に評価対象外になる

探索:

1. 固定席を配置する。
2. 残りの生徒と有効席を試行ごとにシャッフルする。
3. 前方条件の厳しい生徒から、指定範囲内の空席へ配置する。
4. 残りを空席へ配置する。
5. 前後・左右・斜めの8方向で「離す」違反を判定する。
6. 前方違反と「離す」違反を各1点として、通常条件スコアを計算する。
7. 直近2回について、同じ席を2点、前後・左右・斜めの隣接席を1点として履歴類似スコアを計算する。
8. 通常条件スコアを最優先し、同点の案だけを履歴類似スコアで比較する。
9. 両スコアが0なら即時返却する。そうでなければ最良案を保持し、最大5,000回まで再試行する。
10. 完全解がない場合は最良案と違反一覧を返す。

隣接は座標差で判定する。行差と列差がともに1以内（同じ席を除く）なら隣接である。間に無効席がある2席は座標差が2になるため、隣接とは判定しない。

### 6.3 グループ分け

#### 人数枠

- `floor(対象人数 / グループ数)`を基本人数とする。
- 余りの数だけ基本人数+1のグループを作る。
- 固定人数が`ceil(対象人数 / グループ数)`を超えるグループがあれば実行停止する。
- 増員枠は、固定人数が多いグループを優先し、同数なら試行ごとにランダム化する。

探索:

1. 固定された生徒を配置する。
2. 残りをシャッフルする。
3. 空き人数枠へ順に配置する。
4. 同一グループ内の「離す」違反を1組1点で数える。
5. スコア0なら返却し、そうでなければ最大5,000回まで最良案を更新する。
6. 完全解がない場合は最良案と違反一覧を返す。

### 6.4 順番決め

1. 除外者を除く。
2. 先頭・最後固定者を残りの対象から取り除く。
3. 残りをFisher–Yatesでシャッフルする。
4. 先頭固定、シャッフル結果、最後固定の順で結合する。
5. 重複・欠落がないことを検証して返す。

### 6.5 手動修正後の再評価

手動修正は制限で拒否せず、結果へ適用した後に同じ評価関数を実行する。違反がある場合は次を表示する。

- 固定席・固定グループから移動した生徒
- 前方指定を外れた生徒
- 隣接または同一グループになった「離す」組
- グループ人数差

## 8. エラーと警告

### 8.1 実行停止エラー

- 名簿が空、対象者0人、全員除外
- 席数不足、グループ数0、グループ数が対象人数より多い
- 固定席の重複、無効席への固定
- 同じ生徒への複数固定、先頭と最後への同一人物固定
- 固定条件だけで人数上限を超える
- Web Crypto APIが利用できない

### 8.2 続行可能な警告

- 同姓同名
- 前方席が数学的に不足している
- 固定席と前方条件が矛盾している
- 「離す」条件が多く、完全解が見つからない
- 5,000回以内に前方・分離条件をすべて満たせない
- 手動修正により条件違反が発生
- 手動修正後にグループ人数差が2人以上

すべてのメッセージを「何が起きたか」「どこを直すか」の2要素で構成する。

## 9. プライバシー・セキュリティ設計

### 9.1 表示文

画面内の常時確認できる位置に、次の趣旨を表示する。

> 入力した生徒名、割り当て条件、割り当て結果は外部へ送信されず、このページを開いているブラウザ内だけで処理されます。ページの表示には、静的サイトへアクセスするための通常の通信が発生しますが、入力内容はその通信に含まれません。

### 9.2 技術的な防止策

- `fetch`、XHR、`sendBeacon`、WebSocket、EventSourceを本番コードで使用しない
- フォーム送信、外部画像、外部フォント、CDN、解析タグを使用しない
- 入力値を`console`、エラーメッセージ、URL、クエリ文字列、フラグメントへ出力しない
- `localStorage`、`sessionStorage`、Cookieへ入力値を書き込まない
- 履歴保存は初期状態でオフにし、説明と同意操作の後だけ有効化する
- 保存対象は暗号化した名簿と直近2回の席履歴だけに限定し、3回目以降を自動削除する
- IndexedDBへはAES-GCM暗号文、salt、iv、スキーマ版だけを保存し、パスフレーズと復号鍵は保存しない
- 履歴の全削除、手動ロック、一定時間後の自動ロックを用意する
- 静的アセットは同一オリジンから配信する
- 本番HTMLにCSPを設定し、`connect-src 'none'`、`form-action 'none'`、`object-src 'none'`を基本とする
- ユーザー入力はReactのテキストノードとして描画し、HTMLとして挿入しない
- 本番ビルドを対象に、外部URLとネットワークAPIの静的検査を行う
- ブラウザテストで割り当て中の外部通信がないことを確認する

静的ホスティングへの初回アクセスでは通常のHTTP通信とホスティング側の一般的なアクセスログが発生し得る。ただし、生徒名・条件・結果はリクエストURL、本文、ヘッダーへ一切載せない。利用端末、ブラウザ拡張機能、ホスティング事業者そのものの安全性はアプリ単体の保証範囲外であることもREADMEへ正確に記載する。

## 10. 印刷設計

- 席替えはA4横、グループと順番はA4縦
- `@media print`と`@page`で指定
- 操作ボタン、設定、警告、プライバシー表示は印刷しない
- 任意タイトルと任意日付を印刷用ヘッダーへ表示
- 生徒名と結果以外の宣伝・SNS導線は入れない
- 結果が未生成の場合は印刷操作を無効化

## 11. アクセシビリティ

- 色だけで状態を区別せず、文字、枠線、記号を併用
- すべての操作へラベルと明確なフォーカス表示を付ける
- タブ順序を画面の読み順と一致させる
- ドラッグ操作と同等のボタン操作を用意
- エラー領域に`role="alert"`、完了通知に`aria-live`を使用
- アニメーション抑制設定を尊重
- タップ対象は十分な大きさを確保

## 13. テスト方針

### 13.1 単体テスト

- 名簿正規化、空行除去、重複検出
- Web Crypto乱数アダプターと決定的テスト乱数
- 除外者の除去
- 座席、グループ、順番の重複・欠落検査
- 固定、無効席、前方、分離、人数均等化
- 不可能条件での最良案と警告
- 5,000回以内での終了
- 手動修正後の違反再評価

### 13.2 UIテスト

- 貼り付けから各モードの実行まで
- 削除確認、ダミーデータ表示、全員復帰
- Undo/Redo
- エラー時に実行されず、修正方法が表示される
- キーボードによる結果変更
- 名簿入力時の離脱警告登録

### 13.3 プライバシー検査

- 本番ソースに通信・保存APIが含まれないこと
- 入力値がURLやログへ出ないこと
- 実行時に入力データを含むネットワークリクエストが発生しないこと
- CSPが外部接続を拒否すること
- 暗号化履歴を正しいパスフレーズだけで復号でき、3回目以降が残らないこと

## 15. MVP受入基準

- 3モードで対象者が重複・欠落せず割り当てられる
- 固定条件が維持され、不可能な固定条件では実行を止める
- 最善努力条件を満たせない場合に最良案と具体的警告が出る
- 結果をマウス、タッチ、キーボードで修正できる
- Undo/Redoと全削除が動作する
- PCとスマートフォンの主要操作が成立する
- A4印刷およびブラウザからのPDF保存が可能
- 入力データが外部送信・永続保存されない
- Instagramを含むSNS要素が存在しない
- 自動テストと本番ビルドが成功する
- READMEに起動、テスト、ビルド、公開、プライバシー、既知の制約が記載される

## 16. 実装時に検証する設計上の注意

- 5,000試行が100人・10×10席でもUIを長時間停止させないか計測する。必要なら試行を分割してイベントループへ制御を戻すか、Web Workerを同梱する。
- ブラウザ標準の離脱確認は、ブラウザによって文言を変更できず、モバイルでは常に表示されるとは限らない。その制約をREADMEへ記載する。
- HTML内のCSPはHTTPレスポンスヘッダーより制約があるため、公開先決定後にホスティング側のCSPヘッダーも設定する。
- 手動変更を許可するため、結果は「自動割り当て時」と「現在」の評価を分けず、現在の状態を常に再評価して表示する。
